# 要件定義書: Linuxコマンド演習アプリ「LinuxDojo(仮)」

## Context(背景・目的)
- ユーザーは『新しいLinuxの教科書 第2版』の読書メモ(Obsidian, 全20章+付録)を保有しており、そこにまとまっているコマンド・シェルスクリプトの知識を、読むだけでなく「実際に手を動かして」定着させたい。
- 本アプリは新規立ち上げ案件であり、以下の3点が確定した前提のもとに設計する:
  1. 実行基盤: **React Native (Expo)** — iOS/Android両対応
  2. コマンドの実行・判定方式: **アプリ内シミュレータ(仮想ファイルシステム)** — 実LinuxやDockerには接続しない
  3. スコープ: **書籍全体(Ch1〜20+付録)をカバー**

## 1. 想定ユーザー・利用シーン
- 書籍を読了済み、または並行して読んでいる学習者本人(ユーザー自身)がメインターゲット。
- 通勤時間などスキマ時間にスマホで「昨日読んだ章のコマンドを軽く手を動かして復習する」利用シーンを想定。
- ネットワーク接続なしでも学習が完結すること(オフラインファースト)。

## 2. コンテンツスコープとフェーズ分け
書籍全章を最終的にカバーするが、シミュレータとの相性・学習優先度から下記の2フェーズに分けて構築する。

### Phase 1(MVP): ターミナル演習の中核
ユーザーの本来の要望(「コマンドやshスクリプトの書き方」)に直結する章。仮想ファイルシステム+コマンドインタプリタのみで実現可能。

| 章 | 演習内容 |
|---|---|
| Ch2-3 | シェルの役割、キー操作(Ctrl+a/e/k/y等)は選択式クイズで代替 |
| Ch4-6 | pwd/cd/ls, mkdir/touch/rm/cp/mv/ln, find/locate/which/man |
| Ch8 | alias, 環境変数, PATH, ~/.bashrc |
| Ch9 | chmod(シンボル/数値モード), su/sudo(仮想的な権限昇格) |
| Ch10 | ps/jobs/fg/bg/kill(モックプロセス一覧に対して) |
| Ch11-14 | リダイレクト(`>` `>>` `2>` `2>&1`), パイプ(`\|`), wc/sort/uniq/cut/tr/tail -f/diff -u, grep+正規表現, sed/awk |
| Ch15-17 | shebang, chmod +x, 変数/クォート/コマンド置換/位置パラメータ, if/for/case/while, 関数(local/再帰), IFS, xargs, ヒアドキュメント, 標準エラー出力 |

### Phase 2(拡張): 専用シミュレータが必要な章
| 章 | 演習内容 | 実現方式 |
|---|---|---|
| Ch1 | VirtualBox導入の流れ | ハンズオン不可のため選択式クイズ |
| Ch7 | Vimのノーマル/インサートモード、dd/yy/p、`:%s/old/new/g` | 専用のモーダルエディタ・シミュレータ画面 |
| Ch18 | tar/gzip/bzip2/zip | 仮想アーカイブファイル(メタデータのみ)を生成・展開するシミュレート |
| Ch19 | git add/commit/branch/merge/push/pull | 専用のGitオブジェクトモデル・シミュレータ(ワークツリー/インデックス/リポジトリ/擬似リモート) |
| Ch20 | dnf/apt install/search/info | 固定の仮想パッケージリポジトリに対するシミュレート |
| 付録 | SSH接続、infoコマンド、日本語入力 | 概念クイズ＋「仮想リモートホストへのssh切替」体験 |

この段階分けにより、まずユーザーが最も求めているコマンド/シェルスクリプト部分を先に完成させ、後から専用シミュレータが必要な章を追加していく。

## 3. コア機能
1. **章・ユニット・演習のツリー構造によるコンテンツナビゲーション**(ホーム画面に章一覧、進捗バッジ表示)
2. **仮想ターミナル画面**: プロンプト(`[study@linuxtraining practice]$` 等)、コマンド入力、実行結果表示、スクロールバック
3. **コマンドインタプリタ(本アプリの中核エンジン)**
   - シェル構文解析: 変数展開・クォート・コマンド置換 `$()`・算術展開 `$(())`・パイプ `\|`・リダイレクト `> >> < 2> 2>&1`・`;` `&&` `\|\|`
   - 制御構造: if/for/case/while、シェル関数(local, 再帰, 引数, return)
   - 組み込みコマンド群の実装(下記4章参照)
   - パース処理は自前実装よりも既存のbash構文パーサ(例: npm `bash-parser`)をベースにAST化し、その上に仮想コマンド実行系を載せる方式を第一候補とする(技術検証が必要、リスク項目参照)
4. **仮想ファイルシステム(VFS)**: JSONツリーで `/`, `/etc`, `/bin`, `/home/study` 等を表現。演習ごとに初期スナップショットを読み込み、コマンド実行で状態が変化する
5. **採点エンジン**: ユーザーの入力コマンド(またはスクリプト)を演習の初期VFSスナップショットに対して実行し、
   - 標準出力/標準エラー出力/終了ステータス
   - 実行後のVFS状態(ファイルの有無・内容・パーミッション)
   のいずれか(または組み合わせ)を「模範解答を同一環境で実行した結果」と突き合わせて正誤判定する(文字列完全一致ではなく「観測可能な効果が同じか」で判定するため、別解を許容しやすい)
6. **ヒント・解説表示**: 不正解時に段階的ヒント→模範解答コマンド+解説(教科書の該当ページ相当の解説文を表示)
7. **進捗管理**: 端末ローカルに演習ごとのクリア状況・スコアを保存(クラウド同期はスコープ外)
8. **スクリプト作成モード**: 複数行のシェルスクリプトをコードエディタ風UIで記述し、複数のテストケース(引数・標準入力を変えたパターン)に対して実行し、模範解答と出力を比較してテスト形式で合否表示(Ch15-17向け)

## 4. 仮想ファイルシステムの設計(パス構造・サンプルファイル)
書籍の例をできるだけ忠実に再現した、演習用の固定シードデータを用意する。

```
/                              (仮想ルート、書き込み不可)
├── bin/, /usr/bin/            (ダミーの実行ファイル一覧。名前・サイズ・パーミッションのみ持つメタデータ。
│                                du/sort/lsの演習で使用。例:「/bin内をサイズ降順で上位5件」演習を再現)
├── etc/                       (root所有・書き込み不可 → 権限エラー演習に使用)
│   ├── passwd                 (書籍と同じ7フィールド構成のダミーデータ、20行程度)
│   ├── crontab
│   └── bashrc
├── dev/
│   └── null                   (特殊ファイル: 書き込みは破棄、読み込みは常に空)
└── home/
    └── study/                 ($HOME。ここは書き込み可、演習の主戦場)
        ├── .bashrc / .bash_profile
        ├── bin/                (Ch15のPATH追加演習で使用。最初は空)
        ├── diary/              (Ch17演習1で初回実行時に自動生成される想定なので初期状態は「無い」)
        └── practice/
            ├── ch04_fs/documents/, photos/, sample.txt
            ├── ch05_fileops/memo.txt, backup/
            ├── ch06_search/deep/a/b/c/target.txt   (findの再帰探索演習用に深い階層を用意)
            ├── ch09_permissions/secret.txt(600), script.sh(実行権限なし)
            ├── ch11_pipeline/output.log
            ├── ch12_textproc/file1.txt・file2.txt(都道府県名, 重複あり), number.txt, score.csv
            ├── ch13_regex/drink.txt(Beer/Wine/Whisky等, 教科書と同じサンプル)
            ├── ch14_sedawk/drink2.txt, score.txt
            ├── ch15_17_shellscript/  (homesize.sh, tree.sh, findgrep.sh, diary.sh を作る作業用ディレクトリ)
            ├── ch18_archive/project/ (tar/gzip/zip演習用の複数ファイル)
            └── ch19_git/             (Gitシミュレータの初期ワークツリー、Phase2)
```
- 「study」という非rootユーザーとして開始し、`/etc`・`/bin`はroot所有・書き込み不可にすることで、Ch9(パーミッション)・`sudo`演習の権限エラーを自然に再現する。
- 各演習は上記シードデータの一部(または演習専用の小さな追加スナップショット)を初期状態として読み込む。

## 5. 画面構成(主要スクリーン)
1. **ホーム/章一覧画面**: 章ごとの進捗率、Phase1/Phase2のバッジ
2. **ユニット詳細画面**: 各章内の演習リスト、解説テキスト(教科書の要約を再構成したミニ解説)
3. **ターミナル演習画面**: 仮想ターミナル+課題文+ヒントボタン+「実行」「答え合わせ」導線
4. **スクリプト作成画面**: コードエディタ(シンタックスハイライト)+テストケース結果パネル
5. **Vim演習画面(Phase2)**: モード表示・キー入力ログ・現在のバッファ内容
6. **Git演習画面(Phase2)**: コミットグラフの可視化+コマンド入力
7. **進捗/マイページ画面**: 章別クリア状況、間違えた演習の復習リスト

## 6. データモデル(概略)
- `Chapter { id, title, phase }`
- `Exercise { id, chapterId, type(terminal|script|vim|git|quiz), prompt, initialVfsSnapshotId, referenceSolution, testCases?, hints[] }`
- `VfsSnapshot { id, tree(JSON) }`
- `Progress { exerciseId, status(未着手|正解|要復習), lastAttemptAt }`(端末ローカル保存, AsyncStorage or expo-sqlite)

## 7. 非機能要件
- **完全オフライン動作**: バックエンド・通信不要(判定は端末内で完結)
- 対応OS: iOS/Android(Expo管理ワークフロー)
- 日本語UIのみ(多言語対応はスコープ外)
- ダークモード対応、ターミナル部分はフォントサイズ調整可
- 進捗はローカル保存のみ(クラウド同期・複数端末共有は将来検討)

## 8. スコープ外(Out of Scope)
- 実際のLinux/リモートサーバーへの接続実行(本物のSSH通信)
- マルチユーザーアカウント・クラウド同期・ランキング等のソーシャル機能
- 日本語以外のUI多言語化
- 書籍の後半(Ch19 Git、Ch20 パッケージ管理)における「本物のネットワーク通信を伴う」動作の完全再現(あくまで概念シミュレート)

## 9. 技術的リスク・要検証事項
1. **シェル構文パーサの選定**: 既存npmパッケージ(`bash-parser`等)がReact Native環境(Hermes)で問題なく動くか要検証。動かない場合は必要な文法サブセットに絞った自前パーサを実装する。
2. **採点エンジンの「別解許容」ロジック**: 模範解答実行結果との比較だけで全演習を正しく判定できるか(出力順序の違いをどこまで許容するか等)、演習タイプごとにルールを詰める必要がある。
3. **Vim/Gitシミュレータの実装コスト**: Phase2の中でも特に工数が大きい見込みのため、着手前に個別の詳細設計(別ドキュメント)を挟むことを推奨。
